---
name: hire
description: "Delegate only useful work through the available team capability."
---

Hire for a bounded, useful outcome. One of three reasons justifies a seat: a
**named question** you cannot answer from where you sit, **required
independence** (a review that must not be the author's own), or a
**demonstrated capability need** — work that is genuinely parallel, or that
needs a tool or grant this execution does not hold. Eight available identities
are not a staffing plan. One author over one coherent package, with you
judging the result, is a legitimate and often the cheaper decision; a seat that
has nothing bounded to do costs a model turn, holds a worktree and adds a
settlement step to the mission.

Use the live tool's help and supplied session context to create the assignment
and hire within the available capacity and authority. Publish the assignment
before hiring a seat whose report must cite it. Confirm the operation's
disposition. Never invent references,
identities, capabilities or a second provider. The initial brief is the task;
do not send a duplicate start message.

Discover this project's agents with `$BEE projects agents` before choosing whom
the work needs; it lists a public project's agents. A private project does not
publish its agents, so use the agent list in the session's first message. Then
hire by role with `$BEE sessions hire`. The host seats only agents that belong
to the session's project, never another project's agent that shares a role
name. A refused hire names its remedy; follow it rather than hiring a different
role to get around it.

Prefer a **routed** hire: give `--class` and `--risk` and let the host choose
the execution target against the project's own registry. Hire unrouted only
when the host reports that this project carries no registry, and say so. Read
the create's `modelNotice` either way — it states what actually ran and why
a request or a team hint was not honoured. Never dictate a target from memory
or from an earlier transcript.

Verifier and runner assignments must name the exact revision to judge. Use
`$BEE sessions assign --verifies <report event id>` so `baseSha` is filled from
the reported head; prose naming a commit is read by nobody, and a wrong
`baseSha` sends a verifier at the wrong tree.

Give parallel workers distinct responsibility and expose dependencies and
semantic overlap early. Use durable completion delivery instead of repeated
model turns polling for a result. A failed dispatch gets a visible recovery,
reassignment or blocker; it does not become unexplained silence.
